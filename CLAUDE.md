# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

web-kit v2: web access for agents through a real Chrome driven by opencli. The stdlib-only
CLI (`webkit`) runs in **local mode** by default: `src/webkit/local.py` drives this
machine's Chrome through opencli adapters (`opencli <site> search`, `opencli web read`)
and fetches files for `download` directly (urllib; `read` is for web pages only, links as
`[text][N]` with the URLs listed at the end), answering in the shapes of the `/v2` API.
`backend = "remote"` talks to the **web-kit server**: the same local.py in a container
(`backend/`), behind `src/webkit/serve.py`. The agent skill is generated from the CLI.

```
src/webkit/             CLI (search / read / download / status / doctor / engines / config / skill);
                        local.py = local mode; serve.py = the server (python -m webkit.serve)
opencli-plugin/         web-kit's own opencli adapters (biorxiv, medrxiv); declared in opencli-plugin.json (monorepo)
backend/                the server image: Chrome + OpenCLI extension (Chrome policy) + opencli daemon + webkit-serve
                        + noVNC under supervisord, all as user webkit; build context = the repo root
skills/web-kit/         SKILL.md + reference.md, generated by `webkit skill install --dir skills/web-kit` — do not edit by hand
tests/                  offline: test_cli (remote client vs a fake server), test_local, test_serve (real server,
                        real CLI, fake opencli); live: test_integration
```

## Server API (port 8082)

| Route | Key | Purpose |
|---|---|---|
| `GET /v2/search` | X-API-Key | `profile` (ordered engine fallback) or `engine`; per-engine outcome report |
| `GET /v2/engines` | X-API-Key | engines, kinds (browser/api), profiles |
| `POST /v2/page` | X-API-Key | read one web page as Markdown (`opencli web read`); a file is `not_a_page` |
| `GET /v2/download` | X-API-Key | stream a file (fetched directly); a paper page / DOI / arXiv resolves to its PDF, other pages are `not_a_file` unless `allow_html` |
| `GET /v2/status`, `/v2/version` | X-API-Key | opencli, extension, plugin, Chrome version (same fields as local status, `mode: server`) |
| `GET /v2/admin/open`, `/v2/admin/ping` | X-Admin-Key | open a URL in the server's Chrome for a person (noVNC) |
| `GET /healthz` | none | `{"ok": bool}` only, for the container healthcheck |

HTTP status per class in `serve.STATUS`; never 401/403 except for keys (the client reads both
as `unauthorized`). Port 6080 is noVNC (websockify basic auth, user `webkit` / admin key).
The opencli daemon (127.0.0.1:19825) and x11vnc (5900) stay inside the container.

## Who does what (local mode)

- Site-specific code (a site's URLs, page structure, API fields) is an **opencli adapter**: official
  ones first; a site opencli lacks gets an adapter in `opencli-plugin/` (site name not used upstream;
  delete ours once upstream has one). Develop with `opencli plugin install file://$PWD/opencli-plugin`
  (a symlink, edits apply at once); users install `opencli plugin install github:huangyrcn/web-kit`.
- webkit stays site-agnostic: one `ENGINES` row per engine (`local.py`: opencli command, row mapping,
  search page for wall checks), chains, result shape, error classes, budget, numbered links, PDF lookup
  for `download`. What a file says is for the agent's own tools.

## Contracts that tests pin

- Error body: `{"error": <class>, "message", "hint"?, ...}`; exit code per class in `client._EXIT_BY_CLASS`.
- CLI exit codes: 0 ok, 1 usage, 2 no results, 3 failed, 4 auth, 5 unreachable, 6 human, 7 busy, 8 blocked.
- `human_required` (a person can pass it in Chrome / noVNC) vs `blocked` (the site refuses this browser):
  `local.wall_kind`; hints tell an agent what to do next.
- `search` first line: `# engines <name>=<ok:N|empty|error:CLASS|skipped> ...`.
- Output budget (`cli.Output`): a command prints at most `--max-chars` (default 4000, cap 20000)
  across stdout and stderr; page text beyond it goes to a file, other overflow to one spill file
  named in the last line; `-o` prints paths only; `--json` never changes the amount.
- An engine never returns `[]` for a page it could not read: it raises a classified error.

## Commands

```bash
PYTHONPATH=src pytest tests/test_cli.py tests/test_local.py tests/test_serve.py   # offline
WEBKIT_INTEGRATION=1 WEBKIT_BACKEND=remote WEBKIT_URL=... WEBKIT_API_KEY=... PYTHONPATH=src pytest tests/test_integration.py
PYTHONPATH=src python -m webkit.cli skill install --dir skills/web-kit   # regenerate the skill after CLI changes
```

Deploy the server: put `backend/`, `src/webkit/` and `opencli-plugin/` of one commit on the host
(`git archive`), fill `backend/.env` from `.env.example` (bind address, keys), host specifics in
`backend/docker-compose.override.yml` (gitignored), `docker compose -f backend/docker-compose.yml up -d --build`.
Pinned upstreams (Chrome .deb `CHROME_VERSION`, Node, `OPENCLI_VERSION`) live in `backend/Dockerfile`;
`/v2/version` reports Chrome and the image tag. Bump Chrome deliberately: a version change voids every
Cloudflare pass (cf_clearance) the profile holds.

# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

web-kit v2: a self-hosted web access service for agents. One backend container
runs a real, logged-in Chrome and exposes one authenticated HTTP API (`/v2/*`).
A stdlib-only CLI (`webkit`) is the client; the agent skill is generated from it.

```
src/webkit/             CLI (search / read / download / crawl / status / doctor / engines / config / skill)
backend/                Docker image: Caddy + webkit-api + Chrome + SearXNG + noVNC (supervisord)
backend/app/webkit_api/ FastAPI service (the API)
skills/web-kit/         SKILL.md + reference.md, generated by `webkit skill install --dir skills/web-kit` — do not edit by hand
tests/                  CLI tests (fake server) + live integration tests
backend/tests/          offline backend unit tests
```

## Backend API (port 8082, Caddy-authenticated)

| Route | Key | Purpose |
|---|---|---|
| `GET /v2/search` | X-API-Key | `profile` (ordered engine fallback) or `engine`; per-engine outcome report |
| `GET /v2/engines` | X-API-Key | engines, kinds (crawler/api), time-filter support, profiles |
| `POST /v2/page` | X-API-Key | read one URL (patchright render, crawl4ai conversion); PDFs → extracted text; `pdf` → the PDF the page links |
| `POST /v2/crawl` | X-API-Key | bounded synchronous deep crawl |
| `GET /v2/download` | X-API-Key | stream a file through Chrome (cookies apply); a paper page resolves to its PDF (`citation_pdf_url`), other pages are `not_a_file` unless `allow_html` |
| `GET /v2/status`, `/v2/version` | X-API-Key | browser, egress (TLS probe), engine health, versions |
| `GET /v2/admin/open`, `/v2/admin/ping` | X-Admin-Key | open a URL for a human via noVNC |

Ports 6080 (noVNC, basic auth `webkit` / admin key) and 9223 (raw CDP, X-Admin-Key)
are admin-only. SearXNG (127.0.0.1:8080) and `/internal/*` are never exposed.

Crawler engines (Chrome-rendered, `serp.py`): google, duckduckgo, google_scholar,
semantic_scholar, arxiv. API engines go through SearXNG (`searxng.py`).

## Contracts that tests pin

- Error body: `{"error": <class>, "message", "hint"?, ...}`; classes in `errors.py`.
- CLI exit codes: 0 ok, 1 usage, 2 no results, 3 failed, 4 auth, 5 unreachable, 6 human, 7 busy, 8 blocked.
- `human_required` (a person can pass it in noVNC) vs `blocked` (the site refuses this server): `download.wall_kind`.
- Error hints tell an agent what to do next (`errors.human_required` / `errors.blocked`).
- `search` first line: `# engines <name>=<ok:N|empty|error:CLASS|skipped> ...`.
- Output budget (`cli.Output`): a command prints at most `--max-chars` (default 4000, cap 20000);
  page text beyond it goes to a file; `-o` prints paths only; `--json` never changes the amount.
- An engine never returns `[]` for a page it could not read: it raises a classified error.

## Commands

```bash
uv run --with pytest --with fastapi --with httpx --with pypdf --with patchright \
  pytest backend/tests                                    # backend unit tests (PYTHONPATH=backend/app)
PYTHONPATH=src pytest tests/test_cli.py                   # CLI tests
WEBKIT_INTEGRATION=1 WEBKIT_URL=... WEBKIT_API_KEY=... PYTHONPATH=src pytest tests/test_integration.py
PYTHONPATH=src python -m webkit.cli skill install --dir skills/web-kit   # regenerate the skill after CLI changes
```

Deploy: copy `backend/` to the host, fill `.env` from `.env.example`, copy
`searxng-settings/settings.yml.example` to `settings.yml`, `docker compose up -d --build`.
Pinned upstreams (SearXNG commit, Chrome .deb `CHROME_VERSION`, Python packages) live in `backend/Dockerfile`
and `backend/app/requirements.txt`; `/v2/version` reports them. Bump Chrome deliberately:
a version change voids every Cloudflare pass (cf_clearance) the profile holds.
